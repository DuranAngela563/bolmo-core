# Phase 0 profiling — Bolmo

This is the first profiling step of the LayerSkip-style adaptive-depth thesis.
The goal is only to understand where time and memory are spent in Bolmo.

## What it does

`profile_phase0.py` loads Bolmo through HuggingFace and profiles:
- Prefill latency
- Generate-total latency (`model.generate()` fallback mode)
- Generate-total bytes/s and time per generated byte (max_new_tokens controls generation length)
- Peak GPU memory (allocated/reserved)
- Estimated KV cache size (when cache is exposed)
- Component timing for:
  - `model.local_encoder`
  - `model.local_encoder.boundary_predictor_module`
  - `model.layers` (global backbone)
  - `model.local_decoder`
  - `lm_head`
- Per-layer timing for `model.layers[i]`
- Patch stats (num patches, patch lengths, summary quantiles)
- Boundary confidence stats (if available)
- Module detection metadata (`components_found`, `components_missing`, `global_layers_path`) and optional `--inspect-modules` printing

## Run

```bash
cd master_thesis/bolmo-core

python thesis/profiling/profile_phase0.py \
  --model-id allenai/Bolmo-1B \
  --device cuda \
  --dtype bfloat16 \
  --num-warmup 2 \
  --num-repeats 5 \
  --max-new-tokens 128

python thesis/profiling/analyze_phase0.py \
  --input-dir outputs/profiling/<run_folder>
```

Local checkpoint example:

```bash
python thesis/profiling/profile_phase0.py \
  --model-id /abs/path/to/Bolmo-1B \
  --local-files-only \
  --device cuda --dtype bfloat16
```

## Limitations

- Decode mode is currently `generate_total_fallback` (timed `model.generate()` total), so this is not pure cached decode timing.
- Component timings can overlap (for example, `boundary` can be inside `local_encoder`), so component bars are diagnostic and not guaranteed to sum cleanly.
- Hook timings synchronize CUDA at each hooked module/layer, so component/per-layer times can be inflated. Interpret fractions as relative attribution, not exact percentages.
- If boundary/patch internals are unavailable in model outputs, fields are kept as `None` and scripts continue.
- `max_memory_reserved` is affected by CUDA allocator caching behavior.
- OLMES remains for quality evaluation; this tooling is for efficiency bottleneck analysis.
